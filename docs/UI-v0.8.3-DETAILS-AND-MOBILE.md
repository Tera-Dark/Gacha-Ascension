## 交互原则

**默认只展示当前行动必须知道的数值，主动点开才显示完整计算和来源。**

不将大段天赋、卡牌概率、角色拆分统计持续挤在屏幕上，也不因为手机隐藏右侧角色栏就失去属性查看功能。所有详细信息统一使用浏览器原生 \`details/summary\`，默认**关闭**，在当前系统就近查看；打开后立即从真实游戏存档和战斗引擎重算，不使用固定演示数值。

- **战斗探索**：优先显示地图、战斗、血条、自动刷怪、挑战按钮、刷怪目标、进度；下方“战斗属性详细数据”折叠包括主角和敌人实际攻防血、境界基础乘区、卡牌加成、命中/回避、减伤、功法克制、输出间隔、实际UI挂机间隔、守卫模拟胜率和多波阵容。
- **修炼突破**：保留当前修为/悟道两条进度条与可否突破；详细展开显示公式 \`ceil(100×2.35^阶段序号)\`、额外增益、剩余资源、Boss资格、丹药和保底；20个境界的长名单另行折叠。
- **七种卡包**：卡包入口及单抽/十连价格保留可见；“卡池数值与全部掉落概率”展开展示当前每抽成本、累计抽数、实际稀有度概率、各卡牌效果与库存。对稀有度没有对应卡的池子使用与引擎相符的重分配权重，不直接照搬全局65/25/8/2。
- **功法 / 洞府 / 灵宠**：可装配卡继续可见并支持触屏点选；折叠内容提供对应技能生效倍率、重复卡份数、经济封顶、护盾、穿甲、稀有永久遗物加成。所有值由实际Selector实时获得。
- **轮回 / 天命**：轮回按钮和因果账户常驻；10件测试常规遗物和鸿蒙图鉴的长列表默认折叠。深层详情提供累计Boss与轮回记录、40因果箱、品质权重、**0.01%鸿蒙独立追加概率**与实际永久增益。
- **世界图鉴**：前四张已可玩地图保持可见，后20张规划地图默认折叠；另提供当前地图强度与奖励指数倍率、Boss属性来源。
- **存档设置**：导出、备份重开是主操作，Schema、内部存档键、抽卡/战斗账本、累计灵石收支折叠显示。详细面板无权修改存档。

## 手机交互重新组织

手机的九个功能按钮不再以水平小字按钮硬挤到一个横向滑动列表里。

- **固定五个入口**：探索 / 修炼 / 抽卡 / 轮回 / 更多，五列随设备宽度等分、真实最小高度52px（按钮目标不少于44px）。
- **更多系统底部弹层**：功法、洞府、灵宠、图鉴、设置与常用系统共同放在两列大按钮内；背景有遮罩，选择后自动关闭，点击遮罩、关闭键或按Escape也能收起。
- **操作优先级**：探索的自动刷怪与挑战按钮始终排在可选战斗详情之前；避免展开的属性表把所有核心按钮推走。
- **自适应触控**：按钮宽度使用网格与\`minmax(0,1fr)\`，字级使用\`clamp()\`，触控高度约44–52px。较窄屏幕自动由三列变两列；主按钮占整行，消除误点；背景安全区兼容手机底部手势条。
- **屏幕高度**：保持顶部资源和底部导航，中间当前系统单独滚动；400px以下仍可通过更多弹层访问所有系统；防止九系统横向溢出。
- **性能**：详细数字仅在其折叠面板展开时生成真实DOM；关闭时清空隐藏表格。自动刷怪结算无需反复重绘9套数值表格。
- **可访问性**：保留原生 \`summary\` 键盘操作、可见焦点、更多系统的 \`aria-expanded\` 与对移动端导航的清晰标签。尊重系统减少动画的设置。

## 明确保留的范围

- 当前是四图 / 炼气到筑基初期切片，剩余20张地图只是规划图鉴；不因为多了详情就伪装24图已经可玩。
- \`v0.8\` 的Schema 8和LocalStorage key仍然不变，更新详情与移动布局不清空旧试玩档；早期v0.7.1存档独立。
- 卡牌随机掉率、修为公式、地图奖励、怪物难度、本世装备归属、Boss逻辑一概不改。
- 背景挂机仍有旧版前台/后台限制，没有改成Melvor的长时间离线结算。

## 建议玩家验收路线

1. 用手机打开试玩，确保「探索」「修炼」「抽卡」「轮回」「更多」五个按钮都明显且可点。
2. 在探索页面点「战斗属性详细数据」，检查自己的攻防血、命中、减伤、当前敌人、守卫波次与胜率；收起后，核心战斗按钮依然在上方。
3. 抽一张战力卡，回到探索，展开详情确认攻击加成数值发生改变。抽修为卡后到修炼页检查悟道与成本。
4. 点「更多 → 洞府」，抽洞府卡后展开洞府收益详情；切换灵宠和功法，观察战斗细节变化。
5. 到机缘抽卡展开卡池概率，比较不同池子的实际有效稀有度与各卡牌库存，验证缺档稀有度重分配。
6. 打开世界图鉴，检查后20张地图默认隐藏；打开轮回/天命，确认未持有的遗物不会默认占满手机页面。
7. 让自动战斗继续运行并展开详情，验证数值变动不会阻断挂机或重置面板开关。
8. 刷新页面检查原试玩存档、地图进度、选定灵宠与折叠默认状态。

> 本版判定标准：不是数值越多越好，而是「当前任务、关键按钮一眼可见；有疑问的玩家能在原页面一键追溯完整数值和来源」。
