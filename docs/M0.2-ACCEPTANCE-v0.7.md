## 当前版本最重要的三件事

1. **战斗 → 抽卡 → 战胜瓶颈**：从旧版纯数值推图升级成机制驱动关卡，失败时进入已通关层刷灵石，新的卡或免费切换的主战特性能够改变实际伤害和存活。
2. **玩家能理解为什么失败**：战斗上方显示与实际相同种子的预演结论；下方给出防御、爆发、修为封顶、突破丹等原因与目前已开放的推荐卡包。
3. **随时能抽卡**：手机版底部“探索/抽卡”快捷入口，抽卡后显示真实敌我数值与本关胜算的前后变化，避免结果只显示百分比标签。

## 当前可玩内容

- 青云山麓普通 **30层**，第5、10、15、20、25、30层各配置精英或首领机制。
- 初始战力秘藏，5层聚财机缘，10层修为造化，16层丹道宝匣；共 **28张卡牌**，其中战力类新增四张可装配主战特性卡。
- **主战特性只能同时装备1个**：连斩剑意、裂甲真诀、护体灵光、金身反震。抽到第一张自动上阵；之后可以在“本世功法与藏品”列表中免费切换，重复抽中同名增加效果，上限由引擎定义。
- 第20层后仍需要 Lv.12+筑基丹×1 并主动突破，**达到境界锁时，抽卡和更换特性不会偷偷自动推进21层**。
- 失败自动退回最近一次有效通关层发育；手动可以选任意已经通关的扫荡层。抽卡或切换特性之后，只在下一关真实战斗预测获胜且无境界锁时才会切回冲关。
- 灵石资源主要来自战斗（含初次通关一次性补偿），按关卡 / 聚财卡 / 当前难度计算，经济倍率有硬上限；没有直接消耗灵石加属性按钮。
- 当前存档使用 **Schema v3**、\`gacha-ascension-m0-v3\`，与 v0.1、M0 初版、M0.1 独立；新版存档备份/重开不会覆盖旧游戏。

## 玩家验收路线

| 阶段 | 实际操作 | 合格体验 |
|---|---|---|
| 开局 | 首抽战力秘藏，开启自动探索 | B-01 攻击提升，战报与预测可察觉变化 |
| 第5层 | 解锁聚财包；选择投资一次还是继续战力 | 刷灵石效率变得可见，但卡包投资并非无代价 |
| 第10层 | 遇到玄甲守关，抽战力秘藏并尝试装备裂甲 | 破甲有效减少受防御影响的伤害损失；高防关不再只是等综合战力大于门槛 |
| 第15层 | 面对开场爆发敌人，试切换护体/生存特性 | 护盾吸收在战报可见，失败原因可以解释 |
| 第16–20层 | 丹道宝匣抽筑基丹并继续提升等级 | 第8次丹道抽卡必能获得筑基丹；没有丹药不能偷过21层 |
| 第21–25层 | 筑基后探索遇到持续回复的妖藤 | 增益和对策体现在战斗回合，而非单调属性对碰 |
| 第30层 | 终章首领兼具玄甲与开场爆发 | 玩家可以明确选择应对机制而非只增加攻击 |
| 通关后 | 手动扫荡已通关层；刷新、导出存档 | 状态与卡牌、装备记录不丢失；不误进入未实装下一地图 |

## 游戏规则的真实实现与边界

**阵营机制**：
- \`iron_shell\` 强调目标高防（通过关卡数值体现），\`thick_hide\` 提高敌人生命；
- \`first_burst\` 使敌人首回合攻击更猛烈；
- \`regeneration\` 在每次交锋尾部恢复部分生命，上限为敌人最大气血；
- 主角 \`combo\` 每3次主动攻击附加一次输出；\`pierce\`削减目标有效防御；
- \`ward\`开局建立护盾；\`counter\` 在受击且仍存活后反击；
- 以上机制都有统一的纯函数战斗结算与日志；预览使用**同一个 fight() 函数**，并读取当前seed，不是两套相互矛盾的公式。

**抽卡**：除战斗基础修为外，属性、修炼上限、资源获取效率和丹药均由对应卡包获得。首战力抽卡固定B-01；丹道宝匣8抽内保底筑基丹，十连按照单次判定逐抽结算。抽卡不改动旧版永久遗物或轮回账户。

## 自动化验收

~~~bash
npm test
npm run simulate:m0
npm run build
npm run check:content
# 大样本验收（比较耗时，单独Actions工作流支持）
node scripts/simulate-m0.mjs --full
~~~

校验覆盖：
- 真实战斗效果、同seed复现、三围与稀有度、卡包解锁；
- 四种互斥主战特性的切换，战斗预测不会消耗正式seed；
- 30层与第20层的真实突破条件，自动重试不能穿透境界锁；
- 同事务重复执行不再发卡、扣费或发首通奖励；过期交易也禁止重放；
- 单抽×10/十连×1概率与收益序列一致；筑基丹8抽保底；
- 收支流水账、灵石不会凭空产生，历史v0.1/M0/M0.1存档不被修改；
- Pages静态资源、主JS语法与所有引用的JSON路径完整。

**注意：** 自动化通过只能证明当前规则/策略闭环，不代表随机策略、人类真实手机触控和长时间收益曲线已达到商业版质量。还需要用户打开 Pages 进行真实试玩。

## 验收反馈最有价值的三个问题

1. 第10、15、25、30层的机制是否真正让你想**换主战特性/改抽卡方向**，还是仍然靠猛抽属性就行？
2. 卡关刷怪到下一次有用抽卡的等待时间是否合适？抽卡后能否明确感到原来打不过的怪变得可以处理？
3. 手机端探索↔抽卡两个主要行为是否快捷？自动扫荡与重新挑战是否准确，并且不会不停报错或反复无效失败？

以上三项达标后再引入正式洞府、灵宠与轮回，不把新系统堆在无趣的旧循环上。
