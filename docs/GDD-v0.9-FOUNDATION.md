> 2026-10-22，v0.10.7 现行规则。文件名保留以稳定文档链接。可玩范围：前4／24图、炼气四阶段和筑基初期；历史阶段记录归入 Git，不作为并列规范。

## 现行规则：经营一世，传承一脉

**循环**：抽卡发现功法、灵宠、建筑和配方 → 安排主活动与洞府产线 → 用战备与流派破解关卡 → 选择两席传承并轮回 → 已修境界重修所需修为降低，持续积累见闻、道统和天命。

- **主副线**：修士在探索、采药、闭关中选一项；药田、丹炉独立。回春草与回春丹基础解锁，D002解锁护脉叶／护体散，D003解锁剑意花／剑意散；H001解锁药田。配方的永久发现不等于下世无卡即可生产。
- **生产**：默认药草300／丹药100生产库存上限（不裁剪原有库存）；3个丹炉任务，可按数量或补库存。达标的维护任务暂跳过，缺料暂停等待；各任务保留加工时间。道统可扩容与加排程。
- **时钟**：24小时离线上限，不分首世；统一按事件时间结算，领取频率不改变结果。战斗快照冻结开战时的属性、药品可用量与种子，后产药不倒用于之前的战斗；离线不抽卡、不挑战Boss、不突破、不轮回。
- **机缘**：九包按基础成长／战斗构筑／洞府经营展示；普通抽卡每20抽可额外选择一张当前开放核心卡，跨世留存。1／3／6份节点与最多6份数值计算适用于功法、灵宠、洞府；其他卡牌与永久遗物按自身规则。
- **三流派**：剑意按出手积累并爆发，熟练后压制回复；体修入场护盾、格挡反击、熟练后补盾；御灵隔次主攻触发灵契追击，熟练后附治疗。部分标签可跨固定配对共鸣。四图预警／命中／回血／反震均有明确准备提示，完整逐击日志保留。
- **见闻与传承**：记录发现卡、配方、敌人、最高境界。轮回前可从历史发现的普通功法／灵宠／洞府卡中选2张不同卡，次世各1份；“薪火”变为2份，不继承旧叠层。永久遗物、见闻、道统、定向进度保留，库存、装备、熟练度、生产任务清空。
- **6道统节点**：澄心（闭关+25%）→宿慧（突破悟道-1，最低1）；灵仓（库存翻倍）→分炉（队列+1、炼丹+25%）；薪火（传承2份）→行囊（三草各30、回春丹10）。首抽、首炼丹、首通一图、首突破、首次轮回、进入第三世各首次奖励1点，与因果分开。
- **经济配置**：`data/v8-slice.json/management` 为经营、节点、定向和节奏来源。基础境界修为费用×100；已达境界重修×60%。两至四次日回访为目标，每日三次的实际事务模拟目前首世约16.4小时、二世约8.1小时；并非真人留存结论。旧值×2000会在第二关堆出16–24小时的修为墙（实测等于“卡关”），已下调。
- **极端稀有不变**：太古十万分之一、鸿蒙百万分之一，独立追加，无保底，不进入定向与传承，不要求抽到才能通关。

### 命痕残卷：剧情与机缘层次

主角在无名残庙醒来，守卷人「阿烬」教其以灵石照亮前人留下的命痕。抽卡在世界内意味着借来一段修行、器物或洞府的传承；挂机经营积蓄资源，机缘决定可以怎样修行。四图终章，残卷写下玩家自己的名字，将本世发现与下一世有限传承衔接起来。第二世有返庙短篇，承认已有传承与已开放道路，避免重复锁回新手阶段。

| 真实主线位置（全局关卡） | 本次引入 | 作用 |
|---|---|---|
| 1：无名庙中醒来 | 战力秘藏 | 首抽必定强化攻击，体验借来的一剑 |
| 2：首卫之后 | 功法秘卷 | 首门自动主修，介绍剑意、护盾、灵契 |
| 3：旧物认主 | 器物秘匣 | 10槽装备补空槽；基础战利品池不变 |
| 4：山中借宿 | 洞府营造 | 灵田、聚灵阵、云台与蕴兽台支持经营／战备 |
| 5：卷外有回应 | 御兽灵契 | 灵宠协战、功法标签共鸣 |
| 6：山高一寸 | 修为造化 | 悟道来自机缘，修为可战斗或闭关积累 |
| 8：渡口长啸 | 首图Boss准备 | 组合已发现能力，识别爆发威胁 |
| 9：进入竹谷 | 聚财机缘 | 引入长期收益投资，提示境界门槛 |
| 10：丹火照旧名 | 丹道宝匣 | 高级配方与突破丹，介绍20抽定向 |
| 17／25：鬼林／剑冢 | 构筑检验剧情 | 提醒压制回复、反震与不同应对方式 |
| 32且四图通关 | 卷末署名 | 解释保留、清空、两席传承与自愿轮回 |
| 全局30以上且本世筑基 | 法器天机 | 独立本命槽，继续修行或选择轮回 |

灵契支线：发现御灵功法T003后，御兽包可提前开放，并出现「命痕唤来同伴」短对话；不要求先随机抽到指定灵宠，也不增加必出、赠卡或额外资源。它提供由核心抽卡改变下一步安排的实例。其他普通包按表中主线开放；基础采药、回春丹、丹炉与安全挂机始终可用。

数值入口为 `data/v8-slice.json/features.unlockAtGlobalCheckpoint`，支线入口为 `features.unlockByOwnedCore`，剧情正文为同一文件的 `story`。解锁由实际最高关卡、当前卡牌及历史持有／抽取事实判断，引擎的普通抽卡和定向选择共同执行；对话、跳过、回看或修改阅读偏好都不改变解锁与奖励。旧档有本世抽取或非装备持有／发现证据的卡包继续开放；基础装备箱不因此提前开放装备包。法器始终受本世境界限制。未引入的进阶导航暂收起，基础功能保留，手册仍可查阅后续条件。

每段对话通常3句，只在首次全新首世自动迎接，其后在「残卷 · 新」主动展开；旧跳过偏好继续尊重。可上一句、跳过或回看已达到的旧页，安卓返回键关闭对话，阅读不暂停既定经营。阅读偏好独立存在 `gacha-ascension-v8-story-reader-v1`，不进入玩法存档，现为Schema10。首次发现、新的1／3／6份机制节点及高品质保留演出，已知普通重复可快捷；揭晓说明新增机制／配方与战力变化，避免只报品质与数值。

### 状态与交易

Schema10沿用原存档键。`run.world` 保存主活动、药田、丹炉排程、时间尾数与结算报告；`run.startingStones` 记录本世开局灵石，灵石流水校验使用存档内数值，调整开局经济不会让旧档失效；`run.recipes/mastery` 属于本世；`meta.knowledge/dao/inheritance/directed` 跨世。Schema8／9升级先备份原始字节，保留卡牌、装备、材料、因果、遗物与冻结的旧战斗，不推测已经消耗的历史卡或补发定向抽数。首个Schema8版本的存档缺少药草、丹药、宝箱、装备与法器容器，迁移会补默认值并要求这些字段存在，避免升级后第一次采药或挂机才崩溃。

回访用 `RESTORE_SESSION` 在同一事务内追加 `meta.returns`（跨世最近5次），`ACK_RETURN`只确认阅读，不结算时间或发奖。普通在线结算不会覆盖历史回访；Schema8／9迁移不补造账单。模块Worker仅计算一个固定结束时间与24小时总窗口，输出经单写会话校验后保存；中断或冲突不提交。Web Locks所有者负责迁移／导入／重开／保存，其他页面只读；旧客户端写入造成字节冲突也会停止当前写入。

事务：`START_ACTIVITY`／`CLAIM_WORLD`／`SET_FIELD`／`QUEUE_BREW`／`REMOVE_BREW`；`BREW`兼容入口改为计时排程；`CLAIM_DIRECTED`／`LEARN_DAO`／`SET_INHERITANCE`。进行中的手动战斗只能经`FINISH_BATTLE`结算；战斗参数被更新导致旧记录无法复核时，`ABANDON_BATTLE`在存档时间结束后放弃本场且不发奖，避免存档被永久锁住。设备时钟回退时结算按0秒处理并保留时间锚点，不承认倒退的时间，也不会把同一段收益重复发放。既有探索、手动实时战斗和轮回命令继续复用；UI不直接发奖。完整工程职责与验证命令见仓库README。

单元测试验证整段／分段离线一致、缺料／满库／目标切换、开战快照、定向约束、六份封顶、传承合法性和原始备份。节奏脚本不强发资源、不修改概率，用真实事务模拟三流派×10种子×三世；另保留显式加速的战斗单项夹具。浏览器回归覆盖手机横竖屏与完整经营轮回流程。

平台版本继续使用本地WebView与同一事务引擎，无游戏后端、付费、广告或云存档；平台认证需要联网，不承诺完全离线冷启动。前台可玩权限来自原生SDK，账号与实名信息不进入JS和游戏导出。设置诊断仅包含版本、Schema、世数、地图、活动与保存状态，由玩家主动复制／提交。公开签名固定，调试包切正式包需先导出、卸载、安装、导入；后续同签名提高versionCode覆盖更新。

发布前保持300组战斗、三流派连续三世正式模拟和Chromium横竖屏回归；首世12–72小时、二世整体中位至少快30%。真机还需冷启动、后台、杀进程、断网、认证受限、8／24小时、导入导出及覆盖更新。没有已知严重阻塞才能提审；真实玩家、设备和审核结果不可由自动测试代签。

隐私政策与用户协议必须填实际运营主体、联系方式、SDK信息和可访问HTTPS地址；现阶段未伪造主体或平台应用配置。接入参数与命令见README。开发者认证、协议签署和正式密钥保管由开发者完成。
手册是可选实践清单，不是每日任务或新的奖励来源。入门、经营、构筑按本世记录；道统、定向领取及首次轮回依据永久记录。装配和药田表示当前状态，卸下／关闭会取消勾选。已有药品不证明亲手炼过丹，传承卡不证明本世抽过卡；不追溯已消耗历史。14项可并行，随机解锁项不会阻塞下一建议；各页「手册」随时重开。基础三步引导的旧跳过偏好继续生效。提示偏好独立存在 `gacha-ascension-v8-guidance-v1`，属于当前设备界面设置，不随游戏档导出；不增加 Schema 字段、不自动开始活动、不代抽、不领奖、不自动轮回。

开局灵石有单一配置源：`data/v8-slice.json/startingStones` 与 `engine.mjs/STARTING_STONES` 同为110，`loadCatalog` 在两者不一致时直接拒绝启动；开局时该数值写入 `run.startingStones`，流水校验读取存档内数值，因此之后调整开局经济只会影响新开的一世，不会把存量存档判成损坏。多标签单写与Worker恢复已处理；大数与实际低端机性能仍待后续验证。

## 地图、境界与战斗

每图7段守卫及最终 Boss，共8个节点。小怪供本关稳定刷取，守卫推进一关，Boss 开放下一图；失败留在当前关。地图列表只用于浏览进度与资料，尚不支持自由返回旧地图刷取。

进入第二、三、四图后，挑战守卫分别要求炼气中期、后期、圆满；未达标仍可刷当前图小怪。突破需要修为、悟道和前一图 Boss 资格；炼气圆满到筑基还需第四图 Boss 与筑基丹。筑基丹由丹道包获得，最多8次该包抽取保障，不由 Boss 直接奖励。

完整时间戳日志用于逐击扣血、治疗、反击和预警。手动战斗以 `PREPARE_BATTLE` 保存冻结快照与真实开始时间，到最后事件才经 `FINISH_BATTLE` 提交战果；中途刷新按原时间继续，不能重复领取。进行中的手动战斗禁止抽卡、换装、突破等改变构筑的事务，洞府仍独立结算。自动探索同样冻结当场构筑，改变设置只作用于后续战斗。

行动上限导致的僵持与真正死亡分开：只有真正死亡会独立判定50%掉装，随机扣一份穿戴中的普通装备并清槽，不扣法器、未穿戴副本、灵石或修为。打不过的小怪会停止安全挂机，避免持续送死。

## 装备、法器与行囊

普通装备10槽：主／副武器、头冠、帽子、衣服、足履、两饰品、护符、腰带。同款双持必须有足够副本。每件只有1–2条攻击／气血／防御／攻速词条；18件普通装备定义由 JSON 提供。第8类装备包全局第3关开放，怪物不直接掉成装。

法器使用独立4槽，筑基／金丹／元婴／化神各开放1槽；当前仅筑基槽可用。第9类法器包还要求对应关卡里程碑。6件法器样例分别作用于攻击、防御、减敌攻或自身攻速，效果与上限集中在 `artifacts.mjs`。

仓库统一显示宝箱、药草、丹药、普通装备、法器、机缘和永久遗物。数量包含已装备和已备战副本，右侧区分可用数量，使用／装备通过既有引擎事务。草药 H001 与洞府卡 H001 使用不同类型命名空间，不能因 ID 相同合并。暂不提供出售、摧毁、随机词条或单件 instanceId。

## 天命与极端稀有

常规天命箱40因果，必得1件常规遗物；黄／玄／地／天／仙权重50／28／14／7／1，阶层无可抽物品时按剩余权重归一化。≥天阶25箱保障、仙阶80箱保障，仅在目标阶层存在可抽奖励时生效。

现有14种常规遗物。基础攻击+2、基础气血+12、战斗灵石+1%、战斗修为+1%四种永久无上限叠层；其他部分词条满额退出池。无上限基础奖不会因收集完成导致死池，也不受本世卡牌收益硬帽截断。

太古与鸿蒙按每箱整体分别独立1/100,000和1/1,000,000判定，先决定是否进入该层，再从未拥有物品选择；两层可同箱触发，不替代常规奖、没有保底、不会进入定向或传承。每层现有4件，效果分修士、灵宠、洞府、功法或战斗收益的专项乘区，不互相无限放大。不以极端稀有作为主线通关或收集毕业条件。

## 界面和工程边界

桌面左侧为系统导航，资源只在顶栏展示。探索双栏分别呈现精简修士配置与主要战斗画面，首屏仅突出开始／停止探索和当前守卫／首领挑战；手动战斗、自动冲关和刷怪目标移入「战斗设置」弹窗。法器与构筑、守关准备、修行和战报记录默认折叠，10个装备槽仍可操作。手机横屏双栏独立滚动，抽屉可点击或从左边缘滑入；竖屏先战斗后配置，保留底部导航。

各模块仅保留一个标题。抽卡短卡片按三组显示，未开放卡包、未发现功法／灵宠／建筑折叠；成长节点仍可展开。洞府以药田和丹炉区分产线，缺料状态可见，完整消耗与暂停原因保留在「收获与库存」。轮回的道统、传承、遗物分区切换；轮回前明确列出清空、保留、传承和下世变化。10个模块说明与完整数值均在标题问号，支持关闭、Escape 和焦点返回。精简仅影响呈现，不修改数值、事务或存档结构。

像素动画使用加载完成的透明 PNG 和固定 Canvas，攻击条、接触帧、伤害与奖励遵循同一真实时钟。图片加载不依赖 `decode()`；缺帧回退到独立透明立绘，运行时不再使用概念界面裁片。主角与首图狼妖沿用既有原画程序关键帧，后3图使用代码绘制的竹谷／鬼林／剑冢与不同敌人轮廓，Boss追加首领标识；尚待真机小屏视听评价。界面支持 `prefers-reduced-motion`。资源来源和复现见 [README](../README.md)。

安卓由 `android/` 打包同一入口、规则和素材，经WebViewAssetLoader加载；debug本地预览无网络权限，release原生平台SDK使用网络与网络状态权限，游戏规则和存档仍在本机。原生宿主接入返回键、前后台切换和系统文件选择器。导入先校验、备份再替换，失败保留原档，实时战斗结束前拒绝导入。网页与安卓进度通过 JSON 手动转移，不能自动同步。当前可安装交付仍为调试签名，未完成物理手机验收、正式签名与TapTap提审；Cocos移植不在首版范围。

现行源码只在 `src/v8/`；数值由 `data/v8-slice.json` 提供。`workbench.css` 为历史 M0 共用，现行样式加在 `preview.css`。保留 `m0.html`、旧图鉴及其依赖，禁止混用旧等级、退层或概率。
