## 一、版本北极星：3条成长线 + 1次真正轮回

**战斗是基本经济来源，抽卡是所有能力内容的入口，系统则让获得的卡牌真实发挥作用。**

~~~text
                   【永久成长】
               因果 → 天命遗物（Meta）
                       ↓
【当世战斗】→ 灵石 + 自然修为 → 选择卡包
                       ↓
     ┌───────────────┼──────────────────────┐
     ↓               ↓                      ↓
  功法/战力          洞府/聚财              灵宠/丹药/修为
  主角战斗构筑       战斗收益与节奏         协同战斗与突破
     └───────────────┼──────────────────────┘
                     ↓
        推过新关 → 筑基 → 第30层首领
                     ↓
        「继续当前世」 / 「轮回结算」
                     ↓
         领取因果 → 天命开箱 → 下一世
~~~

三条成长线：
- **即时（10–60秒）**：击败怪物、增长灵石与修为、获得一张有效卡、伤害/结算速度发生变化。
- **中期（2–8分钟）**：通关一个机制关、解锁一种真正可玩的系统、切换流派、筑基后碾压曾经强敌。
- **长期（跨世）**：轮回得到永久常规遗物、提高第二世效率、逐步完善图鉴；鸿蒙属于超长期稀有追求而非通关刚需。

**本版完成定义**：首次30层通关后可自愿轮回；新世继承已永久开放功能和天命加成，但当世卡牌/建筑/灵宠/修为按契约重置；玩家能比较同一关卡的前后差异。没有第二世实际更快，就不算做完轮回。

## 二、对 v0.7.1 的诊断（已知真实基线）

上一版大样本的实际 reducer 模拟结果（每个策略1000个种子）：

| 策略 | 完成30层 | 平均战斗 | 平均抽卡 | 平均失败 | 平均旧层扫荡 | 终点灵石 |
|---|---:|---:|---:|---:|---:|---:|
| 均衡 | 1000/1000 | 64.3 | 46.0 | 2.9 | 31.4 | 338.6 |
| 聚财 | 1000/1000 | 57.4 | 48.7 | 3.0 | 24.4 | 510.6 |
| 战力 | 1000/1000 | 70.3 | 48.7 | 2.9 | 37.4 | 295.5 |

**不能直接解读成当前游戏很好玩：**这是自动策略胜利率，不是用户留存、操作次数、真实游玩时长。
- 30层之后仍只有扫荡，**没有第二次打开的理由**。
- 大部分卡还是静态数值；4个互斥战斗特性让战斗稍有差异，但尚未形成多系统协同。
- 46–49抽集中在短关卡内，容易从「惊喜」退化成「必须不断点击才能维持进度」。
- 浏览器转后台目前暂停，欠缺真正 Melvor 式的活动时间与离线结果。
- 当前UI采用独立工作台，但功法/洞府/灵宠尚未真正接入，右侧状态对构筑收益的解释深度不足。
- 当前预测直接使用实际持久 RNG seed 推演精确胜负，给玩家暴露了未来结果；应替换为区间风险提示，并在恢复冲关时用明确阈值、重试冷却与真实结果反馈，避免算命式预知。

## 三、首世30层的新体验编排

**不扩张主线层数；先把既有30层变成有完整成长目标的第一章。** 保留0战力、5聚财、10修为、16丹道、20筑基等现行锚点，增加缺失的功法、洞府和灵宠。

| 已通关层数 | 新内容（必须真的能玩） | 教玩家掌握的决策 |
|---:|---|---|
| 0 | 战力秘藏 / 自动战斗 | 第一抽保证有即时攻击提升，4种主战特性随奖池出现 |
| 5 | 聚财机缘 | 灵石用于即时战力还是投资更高收益？ |
| **6** | **功法秘卷** + 仅账号首次免费体验1抽 | 功法提供主动战斗招式/修炼侧重点，体现不同流派 |
| 10 | 修为造化 | 经验与等级上限解锁，避免Lv.10永远停滞 |
| **12** | **洞府建造** + 仅账号首次免费体验1抽 | 通过抽到建筑改变随后每场收益/修炼速度 |
| **15** | **御兽灵契** + 仅账号首次免费体验1抽 | 灵宠独立参与战斗输出、护主，非UI战力虚值 |
| 16 | 丹道宝匣 | 明确筑基丹目标，仍执行8抽指定丹药保底 |
| 20 | 击败守关，Lv.12+筑基丹 → 筑基 | 材料锁与难度墙分离，突破大幅改变交锋过程 |
| 25 | 多机制精英 | 强调功法×灵宠×主战特性的协同 |
| **30** | 青云首领 → **主动轮回/继续修炼二选一** | 永久因果、常规天命箱、第二世更快的新目标 |

**教学规则**：
- 不让6/12/15层的免费抽直接掉指定功法/建筑/宠物：只发「一次指定卡包免灵石抽取资格」，奖励仍由对应池按公开规则结算。
- 系统解锁保存在 Meta，跨轮回不锁回去；具体卡牌/建筑/灵宠等级在当世重置。
- 解锁时60秒内能够实际感知新内容；互相邻近的12/15/16层只展开一项简明新手指引，不连续阻断操作。
- 保留系统真实预览，未施工的子系统绝不开放空入口。

### 特殊关卡内容目标

关卡仍采用数据驱动的 \`EnemyTrait\` 组合，不复写旧30层关卡原始ID：
- 5层：厚血精英；提高首次战力卡的重要性。
- 10层：玄甲敌人；破甲、连斩或实打实的功法构筑有效。
- 15层：爆发；护盾或宠物护主有明确生存贡献。
- 20层：独立筑基；未满足丹药/等级要求，不许自动冲21层。
- 25层：回复+特殊阶段；靠宠物持续输出、功法节奏、爆发路线分别解决。
- 30层：两阶段青云Boss；至少两种不依赖天阶/鸿蒙的通法，并有可解释的战报变化。

## 四、三大新系统只做少量真正有意义的内容

### A. 功法系统：让角色形成流派（P0）

- **6–9张首批功法**，3个明确倾向：剑修速攻、体修坚守、灵修协同。三类都有黄/玄可得，不能依赖天阶才成立。
- 允许 **主修1＋辅修1**，分开主修战斗触发与辅修轻量被动；抽中重复功法自动提升该功法自身阶层/修为上限，不另设灵石直接升级。
- 当前4张「主战特性」保留为**战斗架势槽**，它与功法主辅槽是两个不同职责：架势偏战中策略切换，功法偏长期流派与技能。
- 示例：
  - **流云剑经**：每隔若干次出手追加剑气，配连斩架势后更适合高血怪；
  - **玄武炼体篇**：降低首轮爆发伤害，配护盾形成体修守关；
  - **御灵同心诀**：提高宠物有效伤害，未获得灵宠时只给较弱但有效的基础生存增益。
- 必须有单独的 \`TechniqueState\`、\`TechniqueResolver\` 和战报触发事件，不能把它伪装成战力+15%。

### B. 洞府系统：收益投资真的会回本（P0）

- **3–4种首批建筑**，从洞府建造包抽出：灵田（灵石）、聚灵阵（修为）、行云台（战斗间隔）、蕴兽台（宠物配合）。
- **所有建筑都由卡包获得，重复抽中视为升级/扩容**；不允许「直接花灵石买建筑等级」。
- 洞府仅增强具体来源的收益增量，不产生无限相乘的自循环：
  - 灵田 +X% 战斗灵石；聚财包的其它倍率按组相加/上限结算；
  - 聚灵阵 +Y% 战斗修为；修为包先扩展等级上限；
  - 行云台 -Z% 每次交锋间隔，硬下限保护掉落频率；
  - 功能未解锁时抽池不含只有未来才能实现的建筑。
- 面板显示：建筑层级 / 灵石每分钟（近期真实样本）/ 投资回本估计（基于当前可刷关卡）。
- 平衡要证明早抽洞府、晚抽洞府各有合理取舍，不能全期永远最优。

### C. 灵宠系统：战斗中能看见的第二战力（P0）

- **3–4种首批灵宠**：青狐（持续攻击）、玄龟（护主吸收）、雷隼（破甲/爆发）、可选灵鹿（辅助修为）。
- 通过御兽灵契包抽到宠物，重复同种提升宠物星级或自身成长；**只允许出战一只**，基础宠物也能改变战报。
- 宠物伤害、护盾或回复是独立 \`PetAction\`，不能只叠加主角attack数值。显示宠物实际伤害占比、拯救主角的次数。
- 无宠玩家靠普通功法/战力卡仍可完成普通青云30层；灵宠是构筑选择，而不是隐藏卡死门槛。
- 后续鸿蒙 \`TM-032\` 仅放大宠物最终伤害，不放大护盾、修为与其它系统；避免乘数穿透。

## 五、轮回与天命：v0.8必须验证第二世真成长（P0）

### 5.1 轮回交易

- **第30层首通后开放轮回，但不强制立即轮回。**
- 轮回预览清楚区分：将清空的本世灵石/修为/功法/建筑/灵宠/进度；保留的账号解锁/最佳纪录/因果/天命遗物。
- 因果按 [v0.5 轮回评分候选公式](balance-loop-v0.5.md) 从本世最高有效深度、精英首胜、境界计算；重复刷已通关旧层不能重复获得深度或Boss评分。
- 首次30层预计至少可开 **1个40因果的常规天命箱**（此目标需公式模拟校准，不暗箱发卡）。
- 不能靠故意轮回刷同一里程碑免成本领取首次奖励；后续第二世同关可正常推进但账号一次性赠抽不能重复领。
- 任何轮回与开箱扣费均通过持久事务ID、原子保存与确定性RNG完成。

### 5.2 常规天命与鸿蒙

这里遵循 [天命 v0.5](tianming-relics-v0.5.md) 的正式规则：
- 正式公开天命箱时，**30件常规遗物定义、效果管线、卡池阶位/保底与4件鸿蒙逻辑均要真实可结算**。不可把8件内部测试遗物池冒充正式天命箱。
- 每箱必定有常规奖励（未全毕业前），再**独立0.01%**判定一次鸿蒙；首箱起就有机会，鸿蒙不替代常规奖励。
- 鸿蒙 **不设任何形式保底**，与广告/付费无关，也不作为30层通关必要条件。
- 四件顶级：开天斧×2.5主角普攻最终伤害、始祖印×4宠物最终伤害、洞天珠×3洞府增量收益、大道书×2.5允许的功法正向效果；严格划清每件适用范围并阻止循环放大。
- 普通遗物可稳定叠层，品质阶段允许公开常规保底；全毕业后共鸣余响防止普通池关闭。顶级只是长线超稀有追逐，不挤掉普通稳定成长。
- **第二世表现必须实证**：同等引导策略下通关到第10/20/30层的场次或实际时间比无遗物账户更优，且具体是哪些遗物改善的可追溯。

## 六、放置体验要从「自动点击」变成「活动经营」（P1，不挡P0）

借鉴Melvor Idle的是**持续活动、统计收益、选择任务、离线恢复与多系统并存**，不是复制UI素材。

- 在线：玩家可以在探索、抽卡、功法、洞府、灵宠、天命之间自由切换，已启用的活动继续执行。玩家主动暂停始终生效。
- **离线结算试点**：仅对已有通关记录的安全扫荡关卡执行同一套战斗和奖励算法，绝不离线自动打Boss、突破、自动抽卡或轮回。
- 拟议首世离线收益上限 **15分钟**、首次轮回后上限 **2小时**，上限与效率需测试确认。离线开始前保存已选定的扫荡目标、装配快照、活动速率和最后活跃时间戳。
- 使用批量可验证的 \`SIMULATE_OFFLINE_BATCH\`，按种子与余额按事件顺序结算，防止刷新造成重复发奖；不能仅用「离线时长×平均灵石/分」绕过首通/保底/境界规则。
- 离线报告：「有效时长、战斗场次、灵石、修为、达到等级上限、失败次数」，允许一键关闭。
- 本地GitHub Pages存档无法可信防改系统时间，说明浏览器本地模式可作弊；不应把客户端时钟当反作弊依据，未来云账号上线再讨论服务端校验。

> 若P0工作量过大，离线系统延后到v0.8.1，但整个活动架构应在v0.8中提前预留数据字段。不能用假离线资源冒充完成Melvor式玩法。

## 七、经济与游玩曲线：控制真正的节奏，而不是拖长计时器

以下为候选验收目标，不是承诺值，不应靠提高战斗间隔强行满足。

| 指标 | v0.7参考 | v0.8目标区间 | 验证方法 |
|---|---|---|---|
| 首次主要战斗获胜 | 可正常获胜 | **5秒内看到第一个有效战果** | 真人首次进游戏 |
| 第一次抽卡后的有效反馈 | 单卡+属性 | **10秒内看到下一次战斗差异** | 同敌人与相同装配对比 |
| 解锁每个新系统 | 尚未提供功法/洞府/灵宠 | **解锁后60秒内真实体验一次** | 新手引导/功能扫描 |
| 首世到30层 | 自动策略64场战斗，真人时间未知 | **约12–20分钟主动参与** | 浏览器真实时间埋点 |
| 单世抽卡 | 自动策略46–49抽 | **约30–45次具有价值的抽取**（包含首次免费体验） | 牌池策略模拟 + 真人反馈 |
| 单世有意义的决策 | 主要4类卡包及战术姿态 | **至少5次跨系统的投资/构筑选择** | 事件日志 |
| 可解释的成长反转 | 特殊敌人有机制 | **至少3次「卡关→更换或抽卡→获胜」** | 状态和战报关联 |
| 新世相比首世 | 无第二世 | **前20层所需场次/时间减少约15–35%**（中等普通天命掉落） | 配对账户模拟 |
| 重复低风险扫荡 | 经济仍很靠重复刷 | **大部分扫荡都有清晰可见的短期目标和收益预测** | 卡关等待时间分布 |
| 轮回常规天命 | 不存在 | **首世正常30层至少获得1箱资格** | 评分公式与模拟 |
| 稀有和进度公平 | 丹药保底8抽 | **普通零高阶卡也能跨越普通主线门槛** | 极端坏运模拟 |

重要补充：
1. 让单次抽卡有明确内容，而不是只为降低次数而调高价格；
2. 避免过强的「怪物随机战力」造成运气差死锁；
3. 强化的最佳解释指标是**需要几回合打死眼前怪、能多扛几击、每分钟收益变化**，综合战力数字仅作辅助；
4. 预演不要偷看实际RNG种子给出百分百确定的「这场必赢」，改为基于固定样本/解析计算的胜率区间，并保留战败后的人工重试与安全退层。

### 建议的三个新手节奏大高潮

- 第一个：战力卡 → 6层功法有招式 → 10层攻破玄甲 → 真正第一次体系成型；
- 第二个：洞府改善经济 → 灵宠独立战斗 → 20层备齐突破 → 筑基威力碾压；
- 第三个：30层艰难击败首领 → 轮回开天命箱 → 第二世明显比第一世更快。

## 八、开发架构与长期扩展门槛

目前 \`src/m0/\` 分离了 \`catalog\`、\`state\`、\`combat\`、\`engine\`、\`storage\`、\`ui\`、\`presentation\`；v0.8遵循已有分层，而不是把所有系统塞回 \`ui.mjs\`。

建议结构（命名候选）：

~~~text
data/codex/codex.v0.8.json       正式内容权威源（版本升级）
data/encounters.v0.8.json        仅配置机制/权重差异，不重复实体主表
src/core/
  catalog.mjs                     数据Schema校验/解锁解析
  state.mjs                       Run/Meta唯一归属与验证
  effect-resolver.mjs             正向效果顺序、封顶、乘区
  combat.mjs                      纯函数战斗，英雄/功法/宠物统一事件
~~~

**迁移原则**：
- 已存在的 \`gacha-ascension-m0-v3\` **不能覆盖**。新版本可以新建v4存档，提供明确的「升级当前存档」操作；只要有不兼容卡牌或者首通解锁变更，一律备份、验证、事务成功后再切换新版本。
- Meta和Run的首通/免费抽资格严格分离；跨世清零只能对Run层生效，元数据和RNG保留连续。
- 预览、离线结算、真实战斗与天命箱必须共享同一规则数据源，不得各自维护隐形概率。
- 循环依赖方向保持 \`Catalog → Engine/Systems → Selectors → UI\`，可增模块而不动全局大文件。
- 端侧性能与存储：保留最近有限条详细战报；更长线只记统计汇总，避免LocalStorage逐渐超出容量；离线批处理采用迭代状态与窗口确认，不能逐帧渲染成千上万次战斗。
- Github Pages无需后端即可提供本地单机体验，但必须清楚提示本地存档清理风险与导出备份选项。

## 十、量化验收与否决清单

### 工程验收
- 全部已经承诺的卡牌/建筑/宠物/天命效果有对应处理器，未知effect ID不能悄悄忽略；
- 全局抽卡与天命开箱以真实权重和保底回归测试，不同单抽/十连在同种子和同阶段下可复现；
- 5000个随机种子×三种典型策略，再加坏运偏置策略，普通主线不能卡在材料/经济死循环；**没有鸿蒙账号也必须通关**；
- 所有行为原子交易，刷新/连续点按/旧交易重放不产生双发奖与负灵石；轮回跨Meta/Run原子清账；
- v3→v4迁移之前自动备份/校验，失败自动回滚，不对旧版透明覆盖；
- 手机窄屏、桌面720p/900p工作台实际在浏览器中进行渲染/操作验证；功法、洞府、灵宠和天命与导航一致，无空页；
- 天命鸿蒙 0.01% 独立试验，用至少10万次抽箱的统计试验校验边际分布（实际重现测试应使用可控固定seed大量次，单次模拟不能因为极端概率没出就fail）。

### 玩家体验验收
- 前30层能体验到至少3种系统相互作用，不只是各自贡献一个+百分比；
- 至少3次「卡关→正确使用当前可得资源→战胜」，并能在伤害/生存/灵石效率看见原因；
- 首个完整轮回后能体验永久进度，第二世第10/20/30层的实测平均推进效率显著改进；
- 玩家随时能判断下一个有效目标，卡住时有至少一个不用高稀有卡的确定性解决策略；
- 首页看见当前活动、下一次有用抽卡、下一境界/解锁和轮回可能收益；不要弹窗不断打断自动探索；
- 用户访谈/真人试玩优先于自动测试结果；不以「全部seed能通关」冒充好玩。

### 本版明确不做
- 不扩到31–150层，不做完整6套宠物天赋/道侣/宗门/炼丹玩法；
- 不开发氪金、广告SDK、排行榜后端、账号注册/云同步；
- 不假装有PvP、多线程实时服务器或有反作弊的真实挂机排行榜；
- 不为追求分数加入大量没有战斗表现的百分比白板卡；
- 不更改鸿蒙0.01%独立概率，不给顶级遗物隐藏保底、不做付费概率加成；
- 不因为「类似Melvor Idle」就复制其具体资源、美术、角色、图标或可识别的独特界面素材。
