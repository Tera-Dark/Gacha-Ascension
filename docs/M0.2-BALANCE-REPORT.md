## 2. 已实现的真实改进

- 机制精英点：5厚血、10高防、15爆发、20筑基守关、25回血、30高防＋爆发，战斗不会再只显示标签，实际fight()有回合机制；
- 玩家可以装备**且仅装备一个主战特性**，真实战斗以它决定连斩、破甲、护盾或反击；抽到第一张默认上阵，后续装备免费切换；
- 失败退层后的自动恢复不再冒险无脑重试，每次抽卡/切换特性重新推演；即使预测有胜算也必须遵守筑基境界门；
- 经济倍率候选 \`stoneScale=0.20\`，将完全挂机和随意抽卡的结余上万问题压缩到数百级别；经济优先确实可以减少扫荡场数，但不至于直接免费无限抽；
- 预览与实战共用纯函数：同一随机种子得到同一战报，装配/抽卡前后使用对齐种子做效果比较；
- 自动校验包括抽卡事务幂等、旧收据防重放、存档备份、境界锁防穿越、随机卡池与丹药保底。

## 3. 仍未达标的体验指标（必须保留在下一轮改良清单）

- **抽卡频率仍偏高**：规划目标每世约15–30抽，大样本结果为约46–49抽。属于需要真实用户试玩后继续优化的问题，不能凭3000种子全部通关就算达标。
- **推图节奏仍较紧凑**：均衡型约64场战斗，自动间隔加快后可能比规划的8–15分钟短。无法通过单纯把动画拖慢来解决，需增加有意义的关卡决策与挑战。
- **三条策略仍主要在战斗数量上有差别**：各有回本快慢，但没有建立完整的三种功法/灵宠构筑。只有一个主战特性槽和有限的精英机制，暂时不能冒称丰富Build体系。
- **高阶卡与重复卡的抽卡反馈仍在测试阶段**，属性和回合数变化真实，但还需要人类感受到值得追逐的高光时刻。
- **正式第二世还未实现**：到30层之后只有继续扫荡和刷卡，没有真正轮回奖励，不能用本版评价长期留存。
- **移动浏览器仍缺真人手动通关验证**：CI和Pages均成功，仍需检查手机触控、模态遮挡、横竖屏切换、退出重进。

## 4. 可执行的下一步验收

- 在真实手机浏览器试玩完整第1–30层，重点记录第10/15/25/30层是否想切换主战特性，以及第一张机缘到筑基的总耗时；
- 由实际玩家反馈决定抽数目标是否真需收紧到15–30；如果是，优先增加每张功能卡的有效提升与阶段预算设计，而非简单提高售价造成无聊的扫荡等待；
- 正式M1之前，继续至少比较三种具有**不同实战适配性**的战术套路，确认高防/高爆发/高回复各有合理解法；
- 一旦进入M3，还要比较第二世与首世通关时间；没有轮回时不能推断跨世留存。

## 5. 重现方法

~~~bash
npm test
npm run simulate:m0
node scripts/simulate-m0.mjs --full
npm run build
~~~

最后的 \`--full\` 进行3000组种子测试，相对较耗CPU，建议在独立 Actions 工作流或本地 Node 环境运行。当前自动测试通过不代表UI艺术品质、吸引力、留存或广告商业化已经验证。
