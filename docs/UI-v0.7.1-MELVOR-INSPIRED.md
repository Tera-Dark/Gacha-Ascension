# 抽卡修仙传 · v0.7.1「放置战斗工作台」UI / UX 迭代说明

> 当前为**已经实施的界面与表现层改造**。以 Melvor Idle 的清晰系统导航、集中活动界面、生命与攻击间隔反馈作为交互参考，不复制其图像、图标或具体美术素材。  
> Pages 入口：[当前试玩](https://tera-dark.github.io/Gacha-Ascension/m0.html)  
> 公开参考：[Melvor Idle Steam](https://store.steampowered.com/app/1267910/Melvor_Idle/) · [Melvor Idle 新手教程：界面分区](https://wiki.melvoridle.com/index.php?title=Beginners_Guide) · [Melvor Idle 战斗重构与伤害反馈](https://wiki.melvoridle.com/w/V0.21)

## 1. 信息架构：一次只做一种主要活动

**桌面**（满可视高度，分区内部滚动，避免整个网页无限下拉）：

~~~text
┌──────────────────── 全局标题 / 境界 / 灵石 ────────────────────┐
│ 左侧系统菜单 │    顶部4项常驻资源 / 修为 / 通关状态   │角色详情 │
│              ├──────────────────────────────────────┤         │
│ 仙途探索  ●   │               当前活动               │攻击     │
│ 机缘抽卡      │  双方HP与对撞区 / 真实伤害 / 攻击间隔 │气血     │
│ 功法构筑      │  开始自动 / 手动 / 继续 / 扫荡 / 暂停 │防御     │
│ 境界突破      │  数值预测、卡关提示、地图里程碑     │主战特性 │
│ 活动战报      │  切换系统后显示抽卡或背包对应界面   │下一目标 │
│ 设置存档      │                                      │         │
│ -----------  │                                      │         │
│ [后续洞府等]  │                                      │         │
└───────────────────────────────────────────────────────────────┘
~~~

**手机**：顶部紧凑全局资源，中央单个当前系统页面，底部常驻六个触控入口（探索 / 抽卡 / 构筑 / 境界 / 记录 / 设置）。战斗不中断系统切换。单页面滚动仅限当前活动面板，避免整张网页上下一直滚；窄屏主动隐藏非核心路线摘要。

可拓展方式：在 \`m0.html\` 增加一个带 \`data-view-panel="newSystem"\` 的区块，左侧导航与手机功能区增加对应 \`data-view\` 按钮，再在 \`ui.mjs\` 维护显示标题，配合该系统自己的数据域即可。**不允许直接在 UI 写金币收益、抽奖掉落、战斗胜负**。

## 2. 战斗演出（与实际数值同步）

- \`src/m0/combat.mjs\`：权威逐回合战斗演算，产生 hero/enemy/combo/counter/regen 的战斗事件与最后剩余生命。**它是胜负唯一来源**。
- \`src/m0/engine.mjs\`：同一交易结算发灵石/经验、推进关卡，保护账本；不会等待动画才能提交存档。
- \`src/m0/presentation.mjs\`：纯表现层，取最多8个代表性战斗事件，在前端以不超过约1秒的短动画展示交锋。包含：
  - 左右单位短冲刺与对撞闪光；
  - 双血条按事件中的实际剩余生命更新；长回合日志截取首末关键片段，最后使用权威最终生命值收尾；
  - 每次命中的浮动伤害，护盾吸收，连击/反击和妖物回血的不同文字反馈；
  - 胜利/战败即时显示，收益提示闪烁；
  - 真实属性变动的战力数值轻闪；
  - 攻击间隔进度条，随资源卡降低间隔。
- **动画不发资源、不修改存档、不重新投随机种子。** 自动探索在不同系统面板间持续执行，动画重播也不会造成重复收益。
- 用户系统开启减少动态效果时，缩短演出、避免眩目的连续动画；无障碍文本信息保留。

## 3. 数值反馈

- 角色状态栏突出攻击、血量、防御，变更时短暂亮起；
- 顶部灵石/修为/通关层在同一位置持续更新；
- 战斗胜利时立即显示「灵石 +x / 修为 +y」，并标记当前战斗结果；
- 抽卡结果弹窗给出 **抽前→抽后** 的攻击/气血/防御、灵石收益、修为效率和当前关卡胜算；前后推演采用相同种子以降低随机波动造成的误导；
- 主战特性在构筑页免费切换，战斗表现显示其真实伤害/防御机制；
- 失败仍自动退层，点击卡包入口可以随时转到机缘抽卡，不需要整页上下寻找。

## 4. 本次刻意不改的内容

- 不改变上轮 v0.7 已经过3000组种子测试的关卡、卡包赔率或经济系数；
- 不改变角色已拥有的 Schema v3 \`gacha-ascension-m0-v3\` 记录，**无需再次重开**；
- 仍不提供自动离线修炼（真正的 Melvor 式长离线进度必须另外设计带时间戳、上限和重放结算的可信离线模拟模块）；页面转后台自动暂停；
- 后续洞府、灵宠、天命遗物目前是不可点击的导航预留，不假装已经实装；
- 演出并非大规模逐帧美术或完整回合制战斗动画，而是低成本、高反馈密度的数值可视化。

## 5. 验收清单

- 新旧 v3 存档加载正常，人物等级、卡牌、灵石保持不变；
- 桌面无需滚动整个网页即可切换探索 / 抽卡 / 构筑 / 境界；窄屏底部系统栏始终可点；
- 自动探索中切换到抽卡，活动仍继续；抽完卡后再切回战斗，血条和角色数据正常刷新；
- 对撞时左右角色短冲刺，红绿血条变化，伤害浮字，胜利有灵石收益反馈；
- 高防敌人可以展示破甲改善，护盾显示「抵挡」，回血Boss显示恢复数字；
- 选中动画减少偏好时，关键数值与功能不会缺失；
- 切换页面、重复按开始/暂停、弹出十连弹窗、刷新重进不造成重复奖励和报错；
- Windows 桌面 1440×900、Android 约390×844均要做浏览器截图与真实触控验收。

> 下一版在这个导航架构上接功法、洞府与灵宠，优先补真正可持续的离线进度与长线技能树，而不是为每个系统重复建设页面框架。
