## 二、推荐验收流程（建议按顺序）

1. 打开 [M0 页面](https://tera-dark.github.io/Gacha-Ascension/m0.html)，确认第1关敌人、角色三围、当前修为、灵石和30层进度均显示。
2. 点击【单次挑战】，击败第一只怪，检查资源上涨、战报出现回合数/获胜/首通字样；随后点击【自动冲层】。
3. 首次击败第3关后，确认【淬锋／锻体／护脉】从锁定变为可购买。可先购买一次攻击或气血，观察属性与预计所需击败回合数的变化。
4. 继续自动冲层，至少遇到一场战败，检查系统显示扫荡已通关关卡；灵石/修为仍正常增加。强化后再次点击【自动冲层】可继续冲层。
5. 查看第10、20、30关守关标记。到达30关后不应跳去尚未实装的赤砂地图；可以扫荡第30关继续验收。
6. 刷新页面确认数据保留；点【导出M0存档】可以下载JSON副本。
7. 点击【备份并重开】，确认从第1关重新开始，且旧版本 [v0.1](https://tera-dark.github.io/Gacha-Ascension/) 的本地存档没有受到影响。

**注意**：M0 敌人基础数值来自 v0.5 设计样例，在战斗时使用明确的临时调试倍率（见 \`src/m0/catalog.mjs\`）。它用于验证工程稳定性，**不是正式经济曲线、平均首世时长或正式Boss难度**。

## 三、仓库模块分布

~~~text
m0.html                         独立验收台入口
m0.css                          手机优先布局和状态提示
src/m0/
  catalog.mjs                   v0.5 JSON适配、关卡与练功价格
  state.mjs                     单一运行/永久状态、派生主角数据、校验
  combat.mjs                    纯函数战斗与确定性RNG
  engine.mjs                    指令和幂等事务、一次性奖励、战败转扫荡
  storage.mjs                   LocalStorage、安全备份、存档迁移
  ui.mjs                        控件/战报/自动挑战（不直接发奖）
tests/m0.test.mjs               自动单元/集成测试
scripts/simulate-m0.mjs         5种随机种子烟雾模拟
scripts/verify-m0-pages.mjs     Pages静态资源预检
~~~

## 四、可以本地运行的验收命令

~~~bash
npm run check:content
npm test
npm run simulate:m0
npm run build
# 或全部运行
npm run check
~~~

这些命令仅依赖 Node.js ≥20，无需安装前端构建依赖。M0使用原生ES模块在 GitHub Pages 直接加载。

**CI示例结果**：13个自动测试通过，5种不同种子均可抵达第30层，模拟中包含战败与扫荡；这证明工程闭环可运行，**不代表人类玩家的体验已经达标**。正式设计仍需多策略平衡模拟。

## 五、M0 之后不能提前宣称完成的内容

- M1：境界突破、升级曲线与战败推荐的正式平衡、每章玩法精化；
- M2：功法、洞府、灵宠系统的完整领卡、装配、培养与差异化构筑；
- M3：轮回、因果点、普通天命遗物箱、鸿蒙0.01%独立掉落和共鸣；
- 商业化：没有接广告SDK、没有账号云存档、没有支付与后端系统；
- 美术：当前是验收UI，而非正式修仙题材美术资产。

只有 M0 通过实际手机验收后，才建议推进 M1，而不是把原型直接投入 TapTap 发布。
