# 《抽卡修仙传》渐进成长与关卡解锁 v0.5

> **设计待定 / 未实装。** 本文解决“开局内容太少、玩几分钟又无事可做、战力只剩一个数字”的体验问题。  
> 唯一总体入口：[GDD v0.5](GDD-v0.5.md)；遗物设计：[天命系统 v0.5](tianming-relics-v0.5.md)。

## 1. 解锁设计的三条标准

1. **一个新系统要解锁即能玩**：界面按钮出现后，60秒内能免费体验一次真实效果（通过已赚到的基础资源/一次指定卡包免费抽取，不直接从怪物掉落功能道具）。
2. **新内容必须对应当前痛点**：例如首次碰到高血怪后开放“功法”、资源开始不够时开放“洞府”、面对高攻/精英后引入灵宠护主。
3. **解锁应该永久标记，培养进度轮回重置**：账号第一世击破第15层后御兽模块以后都保持开放，新世可以直接抽御兽包，不重复繁琐新手引导。

### 里程碑取“账号普通主线累计首次到达的总深度”

关卡 key 为 `zoneId:difficultyId:floor`；账号主线绝不直接把不同地图各自30层相加以外的非法层数当作解锁。地图主线总深度通过内容表中明确的 `mainlineIndex` 计算。例如青云1–30为1–30，赤砂1–30为31–60，后续地图依序。旧图高难或重复刷怪不会反复触发全局解锁。

## 3. 每段关卡真正要引导一次决策

| 层数 | 对手/障碍 | 新行为 | 不应该出现的结果 |
|---:|---|---|---|
| 1–3 | 弱怪、修为条 | 看连续击杀和第一次升级 | 看半分钟日志但属性没变化 |
| 4–6 | 高血野猪、输出效率低 | 投攻击、解锁功法 | 抽到指定稀有功法才可通关 |
| 7–10 | 高防傀儡+守关大妖 | 体验出伤、培养与第一次守关战果 | 打不过就只能继续无脑十连 |
| 11–15 | 战力小高潮后遇高攻敌人 | 投锻体、防护；宠物加入战斗 | 灵宠只提供右上角+5%文本 |
| 16–20 | 精英压迫、输出/生存两难 | 推介两种不同解法 | 最优策略始终单点攻击 |
| 21–30 | 高防与高攻并存，境域Boss | 利用修炼、功法、洞府、灵宠的组合 | 人物破境只显示数值+10 |

### 首次30层的“3次大反馈”

- **第10层**：首次守关成功，洞府经营开启，怪物击杀速度明显比刚卡关时快。
- **第20层**：新精英挑战和悬赏目标，让玩家有明确的中期动力，而不是只剩一个“继续打怪”按钮。
- **第30层**：境域守关、境界突破、下一地图，以及轮回常规遗物全新追求出现（不能在一个弹框里同时堆出四套复杂教程）。

这三个点是节奏目标，可以分多个点击阶段渐进展示，不需立即弹四张“恭喜解锁！”阻断游戏。

## 4. 日常游玩的三层目标 UI

### 主屏幕的三个可见指标

**眼前目标**：当前第N层敌人气血/双方对战摘要；本次预计灵石/修为。

**短期目标**：下一次有效提升，例如“还差80灵石将锻体升到8级，预计多扛1次攻击”，并显示一键直达按钮。

**中期目标**：离下个10层守关/Boss/突破还差几层；首次突破后的新内容预告。

当出现卡关时，推荐流程：

~~~
第29关失败：受到敌人攻击240 / 你的气血500（3回合倒下）
├─ [锻体+2] 花220灵石 → 预计可多承受1次
├─ [换玄龟] 灵宠界面 → 首回合护主
├─ [练当前功法] 花180灵石 → 减少敌人存活回合
└─ [扫荡第26层] 推荐每分钟灵石、经验以及下次强化预计时长
~~~

**推荐可以包含抽卡“碰碰运气”，但最上方至少有一个确定性可行动方案**。

## 5. 四个持续爽感反馈点

1. **战斗数字可感知**：攻击从50升级到70后不是战力文本+40%，而是怪物死得更快、掉落累计更快、战斗日志有说明。
2. **境界突破有跃迁**：属性获得一次确定增益、突破选择偏向、地图收益上台阶；从“临门一脚打不过”变成“此前守关直接碾压”。
3. **卡牌有长尾培养**：普通卡可以组成有效套路，高阶卡改变战斗/经济策略；重复卡扩大实际可强化等级上限，不仅仅是加一个收藏数量。
4. **轮回反馈有对照**：展示上世达到第30层的用时与本世达成同一层用时、新增的永久天命加成、接下来能挑战的新关卡。

“爽”来自**可理解的因果链：我做了选择 → 角色真的变强 → 怪物打得更快 / 新关卡通了**，不能只靠抽卡特效堆砌。

## 6. 重复游玩：同样的一世有不同解法

### 六种轮回风格的样例

| 路线 | 前期投入 | 中期投资 | 越级目标 | 风险 |
|---|---|---|---|---|
| **速攻剑修** | 灵石优先淬锋 | 功法+剑法宝共鸣 | 快速击败高血Boss | 面对高爆发易被秒 |
| **体修坚守** | 气血与防御 | 护身功法、龟宠 | 抵抗多回合消耗Boss | 推图速度较慢 |
| **御兽协同** | 少量主角强化 | 强化出战灵宠 | 用宠物补输出短板 | 需要合适宠物，前期成本较高 |
| **洞府经济** | 低成本守关 | 灵田/聚灵阵 | 长期收益转为爆发养成 | 回本前冲关慢 |
| **丹药爆发** | 均衡修炼 | 丹药短时战斗增益 | 对关键Boss使用有限增益 | 消耗品不可持续 |
| **混合稳健** | 修炼保底为主 | 根据敌人克制选择一包 | 灵活切换副系统 | 极端峰值不如专项流 |

**可验收的差异**：至少3条路线能在相近成本的情况下打通首30层；路线优势出现在不同敌人类型，不是所有流派共享同一条“综合战力”最优答案。

### 轮回的主动性

玩家卡住时，应提供两个真实选项：
- 本世继续刷一段时间：有确定性提升路径及明确下一目标；
- 轮回领取因果：永久遗物加速下一世，显示预计能节约多少前期资源。

不能设计成“轮回永远比继续玩更高效”，也不能靠长时间挂机才能得到一次永久抽箱。

## 7. 公平稀有与长线期待

- 天命**常规五档**允许保底与叠层培养，让每世结束稳定成长。
- **鸿蒙异宝**只有极低概率独立出，不影响常规箱原本结果、不需要专属付费/广告票券、无保底。
- 拿到鸿蒙后的奖励可强到改变某条流派的强度，但不能成为普通主线强制条件。
- 未得鸿蒙也要有身份标识：境界成就、深层挑战称号、记录层数、洞府毕业图鉴等。
- 图鉴可以显示未知异宝“???”作为探索悬念；从第一次开常规天命匣起便可以触发，无需第100层才能有资格掉落。
- 每个重要关卡解锁不只给新按钮，应当给一次**具体内容的首次体验**，但其功能物品依然通过抽卡获取。

## 8. 数据驱动配置建议

**解锁事件必须独立**：`account_created`（默认探索）、`first_mainline_clear`（主线一次性首通）、`first_realm_breakthrough`（确实完成境界突破）、`first_reincarnation_completed`（真正完成轮回）是四种不同的触发条件。相同深度可以有多个不同的 `featureId`，并需检查前置功能和实际发布阶段。

第6/10/15层赠送的免费抽取权利对应 `PK-001/PK-002/PK-003`；不得直接由地图发放实体功法、建筑或宠物。用户在轮回前没有使用的免费抽取权利保留在账号层，后续轮回也不能重新领同一份奖励。



关卡首次通过映射：

~~~ts
type UnlockMilestone = {
  mainlineDepth: number;
  featureId: string;
  phase: 'P0'|'P1'|'P2';
  rewardPolicy: 'unlock_only' | 'one_free_run_pack_draw';
  previewText: string;
  tutorialId: string | null;
};
~~~

**只从正常账号首次通关事件触发**，每个 `featureId` 唯一领取一次；跨轮回永久开放入口。本世重置的是训练、建筑、宠物、卡池，不重置已开放玩法的资格。

在数据配置中给出系统是否“已实装”和“仅规划”；P1/P2 里的卡包不能因为触发了对应深度而错误出现在 P0 版本。

## 9. 验收 / 失败判断

- 8成首次试玩者能在2分钟内理解强化直接影响怪物战斗（目标，不是现有数据）；
- 30层普通难度的首世通关无需必得天阶、鸿蒙；
- 首世体验3种不同的系统但不被迫浏览3个长教程；
- 卡住后60秒内能做出一次有效的确定性成长投资（至少前30层）；
- 轮回后旧关第一次被碾压时有明确战绩对比；
- 10/20/30层有不同的局部玩法目的，而非仅敌人HP/ATK乘大数；
- 不得从额外难度重复刷首通奖励无限涨因果；
- 天命箱抽取结果与稀有概率一致，鸿蒙绝不能作为隐藏新手福利强制保底；
- 无鸿蒙状态、无灵宠状态、只练功状态都可稳步推进基础主线；
- 上线前埋点追踪“哪层大面积卡死、哪里放弃、为什么不再打开”。

## 10. 开发深度限制

**P0**：仅1–30普通主线，自动探索/数值战斗/修炼/功法/洞府/灵宠/首轮突破；解锁节点为1、3、6、10、15、20、30。先验证玩家是否真正期待下一关。

**P1**：扩到90深度、法宝与丹药、第二境界以及险境冲层；增加更复杂的组合与记录。

**P2**：100/120/150+深度与挑战，丰富遗物图鉴演出和可选高难分支。文档规划不代表内容已开工。

本版不引入第四种可刷货币、不做放置离线无限自动收益、不做复杂实时战斗，也不接真实广告。
