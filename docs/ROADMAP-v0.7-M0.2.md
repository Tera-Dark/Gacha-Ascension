## 0. 版本定位与坚决不改变的设计原则

**M0.2 不是 M1/M2/M3 的全部功能抢跑，而是修复当前 M0.1 评分约4.2/10 的核心玩法纵向切片。**

主循环固定为：

~~~text
自动逐层击杀 → 灵石 + 基础修为
       ↓
侦测下一关瓶颈（输出 / 生存 / 修为等级上限 / 资源效率 / 突破材料）
       ↓
选择一个已经解锁的分类卡包 → 单抽/十连 → 获取卡牌/丹药
       ↓
卡牌通过系统和可解释的效果管线起作用 → 战斗结果与资源效率真正变化
       ↓
自动重试卡关层 → 击败关卡 → 新包/玩法/境界/敌人机制 → 继续
~~~

**硬边界：**
- 不恢复直接花灵石购买攻/血/防或强化等级的按钮；基础修为由战斗自然增加，但修为收益/等级上限必须通过相应卡包成长。
- 怪物只能掉灵石、修为和明确的首通权益；功能卡、材料、丹药、法宝、宠物、建筑均由对应卡包产出。功能卡本身的选择/装配是免费的操作，不是另一条资源养成渠道。
- 自动战斗始终是数值策略型，不增加手操技能、复杂走位与塔防实时操作。
- 一张卡改变何种子系统的战斗/资源逻辑由其 \`effectKey\` 或合法 \`mechanicId\` 决定，UI 不准直接写 \`hero.attack += value\`。
- 继续保留局内 Run / 账号 Meta / 静态 Catalog / 派生 Derived / UI 五层所有权。
- 新版保持青云山麓普通 **1–30层**，第0/5/10/16层四包，第20层的筑基门槛；不急着把青云以外4张未实装地图变成空关卡。
- 不在本轮引入广告、联网、TapTap SDK、鸿蒙概率修改、云存档、新货币。
- 轮回及天命遗物仍是 **M3** 的正式范围。不能把一个无奖励的“重开”按钮冒充完成的轮回系统。

## 1. 为什么要做：M0.1 诊断基线

本轮以前的逻辑模拟（不是人类视觉试玩）使用当前 reducer 与三种策略各20个种子，观察到：

| 观察指标 | M0.1 基线 | 玩家体验问题 |
|---|---:|---|
| 少量有目的抽卡的玩家通关30层 | 20/20；约31.4场战斗、12.3抽 | 推进几乎无阻力，大量卡包作用没有验证机会 |
| 偏好经济抽卡的玩家 | 20/20；约30.5场战斗、19.4抽 | 资源路线回报过高，终点平均结余约1.9万灵石 |
| 首抽后再不抽卡的挂机玩家 | 20/20卡在第19层后反复扫荡 | 系统没有清楚告诉玩家为什么卡住、要投哪包 |
| 首次通关后继续玩 | 仅能无限扫荡、抽静态加成 | 缺少下一轮、玩法挑战或纪录目标 |
| 多数抽到的卡 | 固定三围、收益或修为百分比 | 新品种与重复品种的差异没有形成战斗策略 |

**不可通过单纯再增加50张百分比卡、把怪物统一翻倍、降低出金概率来“补深度”。** 必须实现具有不同解法的关卡问题，并让玩家感知解决过程。

## 2. 本版交付的六个工作包（按优先级施工）

### WP0 / P0 — 建立真正的游戏体验与数值测试基线

- 扩充可复现模拟器：随机种子不少于1000组/策略，可选择 \`newbie\`、\`battle_first\`、\`wealth_first\`、\`balanced\`、\`unlucky\` 五套明确策略。
- 每一关记录 \`combatCount\`、\`clearTimeEstimate\`（估算而不是实测）、\`defeatCount\`、\`farmCount\`、\`drawCountByPack\`、\`earnedStones\`、\`spentStones\`、\`endingStones\`、\`levelCapWaits\`、\`realmGateWaits\`。
- 统计“玩家未主动抽卡时卡在哪层；抽中哪个类型后能否推进；第5/10/16/20层是否真的产生新决策”。
- 不用简单断言“30层通关即成功”；加入每段平均/90分位卡关时间、无死锁、路线差异、财富收益回本等失败条件。
- 支持读取战斗日志和卡牌收益差异的可重复 A/B 快照。

验收：报告能够指出一次卡关的主要原因、扫荡了几次、花了多少灵石、抽了哪张牌、战斗回合改善多少，而非只输出 PASS。

### WP1 / P0 — 30层重新分段设计，而不是敌人全属性机械递增

保留每10层正式守关节点，第5/15/25层安排精英或机制考验。

| 层段 / 节点 | 敌人机制 / 需要解决的问题 | 卡包带来的有效答案 | 期待的玩家感受 |
|---|---|---|---|
| 1–4 | 低压教学、首抽即改变攻击所需回合 | 初始65灵石 → 战力秘藏首抽「破军剑诀」 | 我抽到的卡真的改变了战斗 |
| **5层首个精英** | 高气血/持续消耗，攻击效率受限 | 战力包的攻击/连斩；过关后开放聚财 | 从第一次小墙进入经济取舍 |
| 6–9 | 同种怪反复打得慢，资源投入有机会成本 | 聚财卡先回本还是直接抽战力？ | 抽哪个包会改变接下来的收益速率 |
| **10层守关** | 高防护，单纯堆攻击的边际效果变差 | 破甲/附加伤害等战斗特性；通关后开放修为包 | 发现不同敌人需要不同手段 |
| 11–14 | 达到练气Lv.10自然上限，升级速度下降 | 修为包提升等级上限和经验倍率 | 新包不是摆设，而是解决眼前瓶颈 |
| **15层精英** | 高爆发/高攻，纯堆攻击有生存风险 | 护盾/防御/反击特性 | 防御型抽卡第一次有战略价值 |
| 16–19 | 丹道开放、修为进一步增长；建议提前积累丹药 | 选择是否为筑基丹投入预算 | 有明确的短期目标，不用全靠提示 |
| **20层守关** | 必须先击败守关者；其后打开独立的筑基锁 | Lv.12 + 抽得筑基丹×1，丹道第8抽保底 | 我为突破做了准备，成功有大反馈 |
| 21–24 | 筑基后前段以可见方式碾压此前同级怪 | 已培养的战力/修为卡与突破倍率协同 | 境界突破不只是换标题 |
| **25层精英** | 高血回复或多回合耐久考验 | 连击/破甲/反击之一，普通卡叠层也可解 | 成功挑战混合机制 |
| **30层主线首领** | 双机制关卡（如护甲阶段+爆发阶段），不能只看总战力 | 两条可行路线和不同卡组体验 | 通关像达成一项目标，不是数字+1 |

**前置公平性**：第5层不依赖未解锁的聚财包，第10层不依赖通关10层后才开放的修为包。特殊机制可由已经开放的战力卡应对，抽不到指定高稀有卡也能靠黄/玄卡重复或修为升级走得过去。第20层必须先打过守关，才限制第21层。

对每个特殊敌人定义 \`traitIds\`、明确的日志文案、伤害/防御公式和至少两种有效解法；禁止使用仅UI显示、战斗结算中不生效的“假特性”。长期新境域只用扩 \`EnemyTrait\` 和关卡组合，避免修改战斗引擎主干。

### WP2 / P0 — 让卡牌从“纯倍率”升级为有战术意义的抽卡奖品

**本轮只向现有战力包补充少量机制卡，并调整少部分旧卡**，候选上限从24卡提升到28卡左右；不创建独立的功法/法宝大系统，也不一次扩成100张卡。

提案机制（名称和倍率仍是测试候选值）：

| 机制卡 | 触发 | 核心效果示例 | 能对付什么 |
|---|---|---|---|
| 剑意连斩 | 主角每累计3次有效攻击 | 下一次额外一次普通伤害50%的攻击 | 高血量 / 持续战斗 |
| 破甲真意 | 主角出伤前 | 敌方有效防御-20%～25%（限帽） | 高防护守关 |
| 护体灵光 | 开战时 | 生成最大气血约15%～20%的护盾 | 高爆发 / 生存不足 |
| 金身反击 | 受击后 | 根据防御值提供一次有上限的反击 | 体修路线 / 长回合磨血 |

- 现有固定攻击/气血/防御/资源卡保留，作为可以复利叠层的“基本盘”。**机制卡改变战斗行为，数值卡支撑机制强度**。
- 避免所有机制卡完全自动叠加变成“谁抽得多谁全拥有”：增加**仅1个【主战特性】槽位**，首次抽到新机制时给出推荐，玩家可免费更换。主战特性不等于未来的“主修功法”槽位，未来须通过清晰命名与类型映射，避免覆盖功法角色。
- 未选择主战特性时普通卡仍能过主线；第一张机制卡不必是天阶才有效。
- 同名机制卡再抽到强化自己的参数或触发效率但有硬上限；重复卡仍保留价值。不可通过强制分解/直接花灵石培养产生旁路成长。
- 战斗公式必须有统一 \`effectId\`/触发阶段（战前、主角攻击、受伤、回合结束），明确顺序及每回合的重复触发上限。
- 初期至少能组成三种有意义的风格：速攻（连斩）、攻坚（破甲）、生存反击（护体/反击）；同等预算不同Boss各有优势，不要求三条路线完全一样快。

### WP3 / P0 — 重新校准经济和抽卡节奏，真正让玩家有取舍

**不提前填死新的灵石掉落数值**；先把关卡掉落、首通奖励、卡包成本和聚财倍率集中到配置中，再通过策略模拟拟合目标。

建议的目标区间（正式数值需测算确认）：

| 指标 | 当前倾向 | v0.7目标 |
|---|---|---|
| 30层战斗次数 | 主动抽卡约31次 | 约60–120次，有3次左右可解释的短暂卡关 |
| 整个30层游玩体验 | 太快且多为自动放任 | 首次完整体验目标约8–15分钟，主要靠决策而非人为拉长计时器 |
| 抽卡次数 | 普通策略约12抽 | 首世约15–30抽，其中有主动决定包类型的时刻 |
| 每次有意义的提升 | 多为静态加成 | 主要瓶颈处抽卡后可看到回合数/掉落/生存改善 |
| 普通玩家完赛结余 | 平均约8000灵石 | 以实际策略为准，目标结余不超过约3–5次当前高阶单抽成本，而非几万灵石 |
| 资源流回本 | 极快且可能一条路通吃 | 投资聚财包后约15–30场同层级有效击杀可回本，非无限指数增长 |
| 随机性与保底 | 丹药8抽保底 | 保留并明示，无法依赖抽到天阶才完成30层 |

**三个防经济漏洞规则：**
1. 聚财卡仅增益普通战斗灵石，不能为自己产生免费抽数、保底进度、因果点，收益倍率要受硬帽约束；
2. 已通关层可一直扫荡，但首通奖励只能发一次；高层掉落与本阶段包的价格应匹配，不能刷一次就买十连，也不能卡几十场仍买不起一抽；
3. 达到等级上限时不无穷积累修为，修为包抽中提升上限后能立即兑现有上限的已存经验；任何种子均不得出现修为上限-筑基丹-卡包价格的复合死锁。

**对经济卡的专门校验：** 测“这笔投资需要打多少场回本、此时是否还有足够层数让投资有意义”。第25层才抽的长期聚财卡可能是陷阱，需要提供回本预估或有适度即时收益，而不是靠诱导玩家盲抽。

### WP4 / P0 — 把“自动战斗 + 抽卡决策”放在同一个手机交互闭环里

原来的手机页面把战斗、境界、进度和战报堆完才显示卡包。下一版应按玩家操作频率重新排主视图：

~~~text
┌─────────────────────────┐
│ 境界 Lv / 当前层 / 灵石 │
├─────────────────────────┤
│ 敌我战斗缩略卡 / 战斗状态│
│ 当前敌人机制 / 战败原因 │
├─────────────────────────┤
│ [自动探索]  [抽卡·机缘] │ ← 常驻主要操作
├─────────────────────────┤
│ 推荐目标：先打破第X层   │
│ 建议：战力包/修为包/丹药│
├─────────────────────────┤
│ 最近3条重要战报/新获得卡 │
└─────────────────────────┘
    下方折叠：图鉴/存档/详细日志
~~~

- 手机屏幕下方固定两个大入口：“探索 / 抽卡”；点抽卡弹出或切到卡包页，**无需从最上方滚过整页才能抽一张**。
- 刚刚抽到的卡显示“**对你当前瓶颈的实际帮助**”：例如“破甲后本Boss预计从5回合降为4回合”；无效果时直言“当前敌人防御低，破甲收益较小”。
- 卡关后显示简单诊断（伤害不足/生存不足/等级封顶/境界限制），对应推荐已经开放的卡包；推荐基于同一份 Selector，不得编造战斗预估。
- 失败后默认退到最近通关层；玩家可更换更合适的已清关层，显示大致灵石/分钟，避免资源卡投资失控时无感知。
- 抽卡不会每次阻断自动推进数秒；十连结果可展开、跳过演出、筛选新卡/重复，动画不改变奖励序列。
- 在视野内展示“下一功能解锁还差几层”和“当前差哪种有效提升”；达到里程碑以简短提示出现可立即体验的新内容，不弹数屏长教程。
- 桌面仍保留左右栏，手机不使用同样的大面积双栏压缩。

### WP5 / P1 — 首次通关后的短期再玩目标（不抢先实现假轮回）

当前正式轮回和天命永久遗物属于M3，不能为了包装“留存”做一个无任何真实奖励的轮回按钮。

本轮增加**轻量本地挑战记录**（可作为M0.2末尾的可选任务，不阻碍P0交付）：

- 首次30层通关记录：总战斗场次、各包抽数、击败30层首领时的卡牌组合、卡关次数。
- 通关后可手动选择**重新挑战青云**，可选「速通」「少抽」「经济优先」三种只提供目标与纪录的挑战，不改变永久遗物能力，也不伪造轮回因果。
- 明确写“挑战记录模式（非轮回）”；在未来M3真轮回上线后，把历史纪录与正式轮回结果分别保存，不做虚假迁移。
- 若 M0.2-P0 的3个成长反转仍没验证成功，则此条延后，不用新挑战掩盖原核心弱点。

## 3. 具体交互与系统契约

### 数据权威与类型配置

延用 \`data/codex/codex.v0.5.json\` 的 Zone/Stage/Enemy 稳定ID，不回填或复写已经保留的历史总图鉴。新增候选配置（建议）：

~~~text
data/
  m0-packs.v0.7.json             # v0.6升级后的卡牌候选、概率、卡包配置
  m0-encounters.v0.7.json        # 30层机制覆盖、Boss规则、掉落倍率、目标提示
  m0-balance-targets.v0.7.json   # 策略测试的目标区间，不能混入线上玩法代码
~~~

v0.7形成**新的临时运行游戏配置版本**，长期合入正式 \`codex.v0.7.json\` 时仍只有一份权威源。不要复制一套全新的关卡/敌人基础表，让两个文件分别维护第10层敌人血量。 \`m0-encounters\` 只配置 \`stageId\` 对应的战斗机制、候选奖励系数和表现文本。

~~~ts
type MechanicEvent = "BATTLE_START" | "HERO_ATTACK" |
                     "ON_HIT" | "TURN_END";

interface CombatMechanic {
  id: string;
  phase: MechanicEvent;
  stackRule: "add" | "highest_only";
  cap: number;
  effectKey: string;
}
interface EncounterOverride {
  stageId: string;       // 关联原有稳定StageDef，不重新造怪物名字
  enemyTraitIds: string[];
  rewardScale: number;   // 候选值，最终统一结算
  hintId: string;        // 给玩家看真实机制，不要假文本
}
interface GameCommand {
  type: "DRAW" | "BATTLE" | "BREAKTHROUGH" |
        "SET_MODE" | "EQUIP_BATTLE_TRAIT";
  txnId: string;
}
~~~

### 代码职责（避免再度回退成巨型脚本）

| 模块 | 需改内容 | 不该承担的事 |
|---|---|---|
| \`catalog\` | 加载/校验战斗特性、关卡规则、卡包售价与配置ID | 不存玩家卡牌 |
| \`combat\` | 纯函数实现多阶段战斗及状态效果、日志事件 | 不发灵石、不扣抽卡费 |
| \`engine\` | 事务原子扣费/发奖、卡关后扫荡、解锁和突破 | 不给某一张卡写特判硬编码 |
| \`state\` | 单一拥有的卡牌收集、主战特性槽、各包抽数与保底、境界 | 不保存派生总战力的重复副本 |
| \`ui\` | 手机版信息层级、卡池抽卡呈现、战斗原因与结果 | 不直接改属性/抽奖结果 |
| \`simulate\` | 大量固定seed、不同投资路线的实际结算轨迹 | 不使用与网页不同的独立战斗算法 |
| \`storage\` | Schema v3和旧版独立存档/显式迁移与备份 | 不悄悄覆盖M0.1旧档 |

**存档规则**：已有M0.1使用 \`gacha-ascension-m0-v2\`。如果无法确保新旧卡定义逐项一致，就用独立的新 schema / key，进入时明确提示可保留旧档；若提供迁移，必须备份且写纯函数迁移测试。不能悄悄删除原有进度。

## 4. 开发顺序（有验收门槛，失败不继续堆内容）

| 子阶段 | 任务 | 完成条件 |
|---|---|---|
| **0 / 基线** | 生成固定seed和三种路线的分关卡事件分析报告 | 能重现此前第19层停滞、主动玩家31场通关和经济膨胀现象 |
| **1 / 敌人机制** | 把5/10/15/20/25/30层做成可区分的挑战类型 | 每个机制至少两种有效解法，不能全都靠更高攻击 |
| **2 / 机制卡与槽位** | 加4种战斗特性、选择/切换，并实现真正效果管线 | 相同seed、相同装备可以重放战斗；不同特性有不同胜负/回合差异 |
| **3 / 经济与推进** | 校准掉落、卡包成本、回本和失败自动重试 | 1000种种子与路线分析，无无法恢复的资源/境界死锁 |
| **4 / 手机UX** | 战斗+抽卡高频入口、即时解锁反馈、战败诊断 | 单屏或至多一次主操作切换即可完成“失败→抽卡→重试” |
| **5 / Pages验收** | 更新M0页面、CI、存档隔离、验收清单 | Pages实际部署成功；多种策略都能通关；旧存档未受损 |
| **可选6 / 记录** | 青云30层本地挑战记录 | 有真实记录可重复挑战，但不冒充轮回或永久遗物 |

每阶段开发后先通过自动测试/模拟，M0.2 玩法验收合格前，不开始新地图大规模填充。

## 5. 一票否决项和量化验收

### 阻止交付的功能错误

- 未抽卡即可直接加攻/血/防；任意战斗功能卡由地图直接掉落；
- 新版地图解锁条件误触发，不满足第20层筑基条件就能挑战21层；
- 战败后无可打关卡、扫荡没有收益或自动重试形成死循环；
- 灵石为负、存档变NaN、十连奖品与同seed连续十单抽结果不同；
- 同一交易 ID 可重复扣费或重复领奖，战斗动画触发多次结算；
- 某一普通主线Boss要求抽到特定天阶、或因为未抽到专属机制卡永久卡死；
- 未发布的宗门/灵宠/轮回空按钮在正式可玩界面误显示为可用；
- 改动 \`v0.1\` / \`M0.1\` 老存档而没有备份/迁移说明。

### 需通过的体验指标（目标范围，验收前允许调）

1. **三次有意义的反转**：在最少3个独立机制关，玩家通过有目的抽卡明显改善回合数/存活或真正实现首通，战报可以解释原因。
2. **三条合理路线**：速攻、坚守、经济投资均可不靠天阶卡完成30层，各自的优劣在不同关卡出现，不是一条路线永远最优。
3. **1000种固定seed × 主要策略**：普通保底路径都可达到第30层；随机极差账号可以更慢，但不得不可恢复卡死。
4. **经济消耗真实存在**：普通路线通关不应普遍剩下数十个十连的资源，经济流应可回本但也要付出前期战斗损失。
5. **新包立即有用**：第5/10/16层首次开启的包，玩家可以在当时或稍后通过已赚基础资源进行一次有效抽取；其效果不只是把图鉴数字改了。
6. **提示能实际解决问题**：发生失败时，界面明确说明主要不足、优先级最高的当前可用卡包、抽卡后预计改善；不会鼓励玩家为了已锁的卡包干等。
7. **移动端主循环便捷**：抽卡入口无需翻完整页；失败→抽卡→重试在一次操作切换内完成。
8. **角色差异可感知**：两种装配策略在同等资源投入下，至少在两类Boss上呈现不同的应对成本或战斗回合分布。

**评分目标**：以先前主观4.2/10的原型评价作为基线，争取通过真人试玩把核心游玩性提升到6.5/10左右；这是设计目标，不是承诺结果，更不代替实际试测。

## 6. 哪些内容暂时不做（防止计划失控）

- 不添加第31–150层，不铺量造100张白板卡；
- 不加入另一个游戏货币或稀有升星碎片当抽卡旁路；
- 不提前做复杂背包合成、锻造、炼丹手操小游戏；
- 不制作整套“洞府/宠物/功法/宗门”正式子系统，先保证现有24卡+少量机制卡真的好玩；
- 不推出假的轮回/因果/鸿蒙箱，不为留存硬塞每日任务；
- 不启动广告、充值、社交/联机；
- 不优先进行一轮昂贵的大型美术改造，直到这次的卡关→抽卡→逆转得到玩家认可。

## 7. 用户验收时只需要回答的三个问题

1. **推图被挡住之后，我是否知道该抽哪种卡，而且抽到之后确实马上想回去挑战？**
2. **我抽到新机制卡时，是不是获得了新的玩法手段，而不是右上角战力又加几百？**
3. **这一轮30层通关后，我是否愿意试一条不同的抽卡路线，并且期待正式轮回与后续地图？**

如果有两项是否定，本版不得仅凭自动测试全绿宣布“玩法已完成”。

---

**方案结论：** v0.7/M0.2 先校准30层的“挑战—获取—抽卡—反转”三角闭环，将新增机制与成长反馈做实。等此纵向切片验证通过，再以同一个数据驱动战斗内核扩展 M1/M2 正式功法、洞府、灵宠，最后通过 M3 完成轮回与永久天命遗物。这样能尽可能避免现在直接大量开发、之后又推翻游戏性的浪费。
